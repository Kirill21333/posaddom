## Роли и права (ТЗ 7.5)
* **Диспетчер**: создаёт, редактирует (до закрытия), отменяет заявки; назначает и переназначает исполнителей; видит все заявки и справочники; отчёты по заявкам; история обращений клиента; не меняет справочники услуг и сотрудников, не удаляет заявки.
* **Сотрудник (исполнитель)**: видит только назначенные ему заявки; меняет статус только в пределах выполнения (Выполняется, Выполнена), добавляет комментарии, загружает фото «до»/«после»; свой график и статистику; не создаёт заявки, не назначает, не видит чужие (403).
* **Руководитель**: видит всё (заявки, справочники, отчёты, сводная аналитика), контролирует просрочки и загрузку, переназначает; редактирует заявки до закрытия; не меняет настройки и справочники.
* **Администратор**: полный доступ: справочники услуг/сотрудников/домов/клиентов, пользователи и права, правила автоназначения, настройки, журнал аудита, резервная копия, любые отчёты.
Проверка прав только на сервере (каждый запрос). Пароли bcrypt. Блокировка учётной записи на 15 минут после 5 неудачных входов (settings: login_max_attempts=5, login_lock_minutes=15). Журнал аудита: вход/выход, создание и правки заявок, смены статусов, правки справочников, выгрузки отчётов, смена настроек.

## Бизнес-правила (ТЗ 7.6, реализовать точно)
1. **Номер заявки**: `<префикс категории>-<год>-<6 цифр>`, пример `А-2026-000145`. Счётчик на год в `request_number_seq`, выдача в транзакции с `SELECT ... FOR UPDATE`, сквозной для всех категорий; UNIQUE на `request_number`. Префиксы кириллические А, С, П.
2. **Сроки**: arrive_due=received_at+R(категории), due_at=received_at+S(категории). Аварийная: 30 мин / 24 ч; срочная: 2 ч / 72 ч (календарно); плановая: выезд один рабочий день (пн-пт 09:00-18:00, праздники не учитывать; параметры settings business_start=09:00, business_end=18:00; если поступила в пятницу 16:00, то выезд в понедельник 16:00 «в то же время следующего рабочего дня»), устранение 168 ч календарно. warn_at=received_at+0,75·(due_at−received_at). Снимок в заявке, пересчитывается только при смене категории.
3. **Просрочка**: заявка просрочена, если не «Выполнена»/«Закрыта» к due_at; величина просрочки показывается. Нарушение выезда: нет arrived_at к arrive_due. `arrived_at` ставится при первом переходе в «Выполняется».
4. **Предупреждение**: cron каждые 5 мин: для заявок с warn_at<=now, warning_sent=0, статус не финальный и не done -> уведомление ответственному и диспетчерам (notifications), warning_sent=1. Просрочки: is_overdue=1 + уведомление руководителю.
5. **Автоназначение** (`AssignmentService`): кандидаты - сотрудники со статусом «активен», у которых в employee_services есть услуга заявки, привязанные к дому (employee_houses), в рабочей смене на момент назначения по work_schedules с учётом schedule_exceptions (для аварийных допускается вне смены: `off_schedule=1`, уведомление «вызов вне графика»). Нагрузка L=Σ вес категории по открытым заявкам (статусы assigned/in_progress; закрытые/выполненные не считаются). Выбор: минимальная L, не больше max_load из применимого правила assignment_rules (наименьший priority; фильтры request_category/service_category/section; если правил нет, max_load по умолчанию из settings.default_max_load=9); при равенстве - тот, кому заявку назначали раньше всех. Нет кандидатов: manual_assign_required=1, заявка в очереди, уведомление диспетчеру. Запись в request_assignments (mode auto/manual), статус «Назначен исполнитель» с историей.
6. **Статусы и переходы**: new -> accepted -> assigned -> in_progress -> done -> closed; new/accepted -> rejected; new/accepted/assigned/in_progress -> cancelled. При регистрации заявка создаётся `new`, затем сразу `accepted` («Принята в работу», автор - диспетчер), затем автоназначение -> `assigned`. Каждый переход пишется в request_status_history (дата, время, пользователь; `changed_by` NULL для системы). Закрыть можно только из `done` и только если есть хотя бы одно фото stage=final. После закрытия: нельзя редактировать поля, можно добавить только комментарий с `is_additional_contact=1`.
7. **Клиенты**: поиск по телефону/ФИО; дубль = совпадение телефона и помещения: создание блокируется ответом 409 `{duplicate:{...}}`, пока не передан `confirm_duplicate=true`; решение пишется в audit_log. История обращений клиента: номер, дата, услуга, исполнитель, статус, дата закрытия.
8. **Фото**: JPEG/PNG до 10 МБ, проверка типа по содержимому; хранение в `storage/photos/<год>/<request_id>/...`; запись: дата загрузки, автор, stage, retention_until=дата+3 года (settings.photo_retention_years=3); удаление раньше срока запрещено.
9. **Платные услуги**: при закрытии создаётся charges (сумма из справочника на момент закрытия, basis).
10. **Справочник услуг**: код уникален; платная -> price обязателен (CHECK); бесплатная -> норм. документ; категории иерархические; любое изменение пишется в service_changes (поле, прежнее/новое, кто, когда); удаление услуги с заявками запрещено (409), только архив (is_archived=1; архивные не выбираются в новых заявках).
11. **Уведомления**: сотрудникам (сайт + дубль на e-mail/мессенджер в `storage/mails`): новая назначенная заявка, смена статуса, приближение срока, просрочка. Клиенту (SMS в `storage/sms` + очередь, или e-mail) при наличии notify_consent: регистрация заявки, назначение исполнителя, закрытие. Внешние интеграции (ГИС ЖКХ, РСО) через `integration_queue` с повторами; при недоступности основная работа не блокируется. Аварийные заявки ставятся в очередь передачи в РСО. Заглушки отправки: запись в файлы `storage/mails|sms` и пометка sent; симуляция недоступности: settings.integrations_enabled=0 -> status pending/error с повтором.
12. **Отчёты** (JSON/CSV/XLSX, «PDF» = печатная HTML-страница `?format=pdf` с print-CSS): по заявкам за период (фильтры: дата, категория, статус, услуга, исполнитель, объект), по исполнителям (выполнено, среднее время устранения, просрочки), по платным услугам (сумма начислений), по просроченным (с величиной просрочки), по обращениям клиентов (число обращений на клиента). Сводка руководителя: числа за сегодня/неделю/месяц/квартал и диаграммы (на фронте простые SVG/CSS).

## API-контракт (JSON; сессионная cookie; все ответы `{ok:true,data:...}` или `{ok:false,error:"текст на русском",code?:...}` с корректным HTTP-статусом: 400/401/403/404/409/422)
Префикс `/api`. Даты в ответах ISO `YYYY-MM-DD HH:MM:SS` (Europe/Moscow).

* `GET /ref` -> `{categories,statuses,channels,houses:[{id,address,section_id}],service_categories,positions,employee_statuses,schedule_types,client_statuses,sections,roles}`.
* Requests: `GET /requests?status=&category=&employee=&q=&house=&service=&overdue=1&queue=1&from=&to=&sort=deadline|received&page=&per_page=` -> `{items:[{id,number,received_at,category:{code,name},house:{id,address},premise:{id,number}|null,service:{id,code,name,is_paid},client:{id,full_name,phone},assignee:{id,full_name,short_name,position}|null,status:{code,name},arrive_due,due_at,is_overdue,manual_assign_required,overdue_minutes|null}],total,counts:{all,new,queue,in_work,overdue,closed}}`; сотрудник видит только свои; `GET /requests/{id}` -> полная карточка: те же поля + `description,channel,client{...,email,status},premise,service{...,price,basis,norm_document},assignee,deadlines{arrive_due,due_at,warn_at,arrived_at,completed_at,closed_at},history[{status,status_name,user_name,at,comment}],comments[{id,author_name,text,is_additional_contact,created_at}],photos[{id,stage,file_name,url:"/api/photos/ID",uploaded_by_name,uploaded_at}],assignments[],charge,allowed_actions[]` (строки из: edit,status:in_progress,status:done,status:closed,status:rejected,status:cancelled,assign,comment,photo,comment_additional).
  `POST /requests/preview {category_code,house_id,service_id}` -> `{number,arrive_due,due_at,warn_at,assignee:{...}|null,queued:bool}` (без побочных эффектов; номер - следующий свободный); `POST /requests {client_id,house_id,premise_id?,category_code,service_id,channel_code,description}` -> `{id,number,arrive_due,due_at,assignee|null,queued}`; `PUT /requests/{id}`; `POST /requests/{id}/status {status,comment?}`; `POST /requests/{id}/assign {employee_id|null(авто),reason?}`; `GET /requests/{id}/candidates`; `POST /requests/{id}/comments {text,is_additional_contact?}`; `POST /requests/{id}/photos` (multipart: file, stage); `GET /photos/{id}` (бинарно, с проверкой прав).

Стиль макетов (намеренно простой, «студенческий»): белый фон; левое меню 220 px серое `#E6E6E6` (название «ПосадДом» 22 px bold и «управляющая компания» 11 px серым; пункты 15 px, активный на фоне `#CFCFCF`, bold); заголовок страницы 26 px bold слева (x=250 в макете 1440 px); справа вверху «ФИО (роль)» 13 px и синяя ссылка «Выйти»; кнопки основные `#2F80ED` белый текст радиус 6, вторичные `#D9D9D9` чёрный текст; поля 1px `#999` радиус 4, белый фон; выпадающие списки с «▼»; таблицы: шапка `#D9D9D9` bold 13 px, строки белые с рамками `#BFBFBF`, текст 12 px, просрочки красным `#D32F2F`, «не назначен» оранжевым `#E65100`; блоки-подсказки `#F2F2F2` с рамкой `#BDBDBD` радиус 4. Шрифт: Inter, затем system-ui/Arial. Без иконок, теней, градиентов, анимаций. Адаптивность нужна минимальная (на узком экране меню сверху, таблицы с горизонтальной прокруткой), но на 1440×1024 страница должна совпадать с макетом по расположению и размерам.
Меню по ролям: **диспетчер** - Заявки, Новая заявка, Услуги, Клиенты, Отчёты (как на макетах; очередь нераспределённых и просроченные - вкладки-ссылки над таблицей на странице «Заявки»); **руководитель** - Сводка, Заявки, Услуги, Сотрудники, Клиенты, Отчёты; **администратор** - Заявки, Услуги, Сотрудники, Клиенты, Отчёты, Пользователи, Правила назначения, Настройки, Журнал; **сотрудник** - Мои заявки, График и статистика, Уведомления. Страницы: вход (макет 1); список заявок (2: фильтры Статус/Категория/Исполнитель/поиск, кнопка «+ Создать заявку», колонки № заявки, Дата, Категория, Адрес, Услуга, Исполнитель, Статус, Срок; под таблицей «Показано N из M заявок»); новая заявка (3: телефон -> «клиент найден...» либо форма нового клиента с подтверждением дубля; дом/квартира; категория радио; услуга; описание; фото «до»; справа блок «Рассчитывается автоматически» с номером, сроками, исполнителем - вызывает `/requests/preview` при изменении полей); карточка заявки (4: поля, фото с подписями, история, комментарии, кнопки «Изменить статус» (список допустимых переходов), «Переназначить» (список кандидатов с нагрузкой), загрузка фото, закрытие, отмена); справочник услуг (5: поиск, Категория, Платность, «Добавить услугу» только админу; редактирование/архив по клику); сводка (6); а также простые страницы в том же стиле: сотрудники (таблица + карточка с графиком, специализацией, привязкой к домам), клиенты (поиск, карточка с историей обращений), отчёты (выбор отчёта, фильтры, кнопки PDF/XLSX/CSV), пользователи, правила, настройки, журнал, уведомления, «график и статистика» сотрудника.
Таймер срока в таблице: «просрочено 2 ч», «4 мин», «1 ч 40 мин», «2 дня» (считать на клиенте от due_at/arrive_due, обновлять каждую минуту). Сообщения об ошибках понятные, на русском. Сохранение черновика формы новой заявки в localStorage (по желанию).
